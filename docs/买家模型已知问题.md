# 买家模型（BuyerSimulator）已知问题说明

> 独立文档 · 仅描述买方模拟器设计问题，不涉及系统其他模块。  
> 对应代码：`src/data/buyer_simulator.py`

---

## 背景

本系统用 `BuyerSimulator` 模拟三类买家（Budget / Latency / Quality）对平台报价与检索结果的接受行为。策略层（LinUCB、Q-Net）的状态向量包含 `sla_t`、`budget_t` 等 Query 字段，期望学习「按合同条件个性化检索–定价」。

当前实现存在三个相互叠加的问题，导致：

- 策略状态与买家反馈**因果不一致**
- 三类买家**行为难以区分**
- 主实验中 LinUCB/Q-Net 相对 Fixed 策略**主要通过提价**增收（accept_rate ~98% → ~83%），nprobe 个性化不明显

---

## 问题一览

| # | 问题 | 核心矛盾 |
|---|------|----------|
| 1 | Query 字段与买家决策脱节 | 策略读 `sla_t` / `budget_t`，买家效用不用 |
| 2 | 买家类型与 Query 生成随机独立 | 买家是谁与 SLA / budget 无稳定对应 |
| 3 | 参数与 FAISS 真实分布不匹配 | 手工 θ 偏离实测延迟与 recall |

---

## 问题 1：Query 字段与买家决策脱节

### 是什么

`Query` 有两个合同字段：

| 字段 | 含义 | 示例 |
|------|------|------|
| `sla_t` | 延迟上限（秒） | `0.05` = 50ms |
| `budget_t` | 价格上限（美元） | `0.01` |

**策略层使用了它们**（`src/agents/bandit_policy.py`）：

```
LinUCB 状态 = [U_t×100, accept_rate, latency_ms, k/100, sla_t×1000, budget_t×1000]
                                                      ↑ 策略认为重要
```

**买家层没有使用它们**（`src/data/buyer_simulator.py`）：

```python
utility = (
    sentiment_bias
    + profile.alpha_price   * (profile.theta_price   - price)    # 固定 θ，非 budget_t
    + profile.alpha_latency * (profile.theta_latency - latency)  # 固定 θ，非 sla_t
    + profile.alpha_recall  * (perceived_recall - profile.theta_recall)
)
```

Week 1 的 `buyer_stub.py` 曾有硬约束（超 budget / 超 SLA 即拒），Week 2 换 Logit 模型后未保留。

### 举例

Query：`sla_t = 5ms`，`budget_t = $0.02`，实际延迟 `2ms`，报价 `$0.005`。

| 组件 | 依据 | 行为 |
|------|------|------|
| 策略 | SLA = 5ms | 倾向低 nprobe、保延迟 |
| 买家 | θ_latency = 20ms（固定） | 2ms 相对 20ms「很宽松」→ 延迟几乎不影响决策 |

策略按合同 SLA 学习；买家按固定心理预期反应——**同一 query 上输入与反馈不一致**。

### 影响

- 状态中 sla、budget 两维对 reward 缺乏稳定因果作用
- LinUCB 可能在这些特征上学到噪声
- 「按 SLA/预算自适应」的结论缺乏实验支撑

### 修复方向

1. **硬约束**：`price > budget_t` 或 `latency > sla_t` → 直接拒绝  
2. **软约束**：效用中用 `query.budget_t`、`query.sla_t` 作锚点，profile 只保留 α 敏感度

## 问题 2：买家类型与 Query 生成随机独立

### 是什么

当前流程：

```
build_query()     → 随机采样 k_t, sla_t, budget_t
buyer.respond()   → 随机采样 BuyerProfile（三类之一）
```

两步**互不关联**，可能出现：

```
LatencyBuyer（延迟敏感） + sla_t = 200ms（极松） + budget_t = $0.002（极紧）
```

`scripts/diag_buyer_differentiation.py` 已实现「先定买家类型、再采匹配 SLA/budget」，但 `run_experiment.py`、`compare_bandit.py` 的主路径未采用。

### 期望 vs 现状

| 买家类型 | 期望 sla_t | 期望 budget_t |
|----------|------------|---------------|
| BudgetBuyer | 50–200ms | $0.001–0.005 |
| LatencyBuyer | 5–20ms | $0.01–0.05 |
| QualityBuyer | 20–100ms | $0.005–0.02 |

独立随机下，大量 query 的「买家类型」与「合同字段」语义矛盾。

此外，`respond()` 用 `rng.choice(profiles)` 选类型，与 `build_query()` 不同源；即使 `buyer.rng = np.random.default_rng(seed + i)` 保证可复现，**sla/budget 仍不能代表买家身份**。

### 影响

- 三类买家行为差异被噪声稀释
- Q-Net 难学「Latency → 低 nprobe」「Quality → 高 nprobe」
- 诊断脚本与主实验逻辑不一致

### 修复方向

1. `build_query()`：先 `get_profile(seed + qid)`，再按类型采 sla/budget  
2. `respond()`：用 `_profile_for_query(query)` 确定性选 profile  
3. 抽取公共 `src/data/query_factory.py`，避免脚本间重复

## 问题 3：参数与 FAISS 真实分布不匹配

### 是什么

`BuyerProfile` 的 θ 为手工设定，未按索引实测标定。以 `configs/sift1m.yaml` 为例：

```
nprobe → recall：{8: 0.66, 16: 0.79, 32: 0.88, 64: 0.93, 128: 0.95}
延迟量级：约 0.3ms ~ 6ms
```

| 买家 | 参数 | 当前值 | 问题 |
|------|------|--------|------|
| LatencyBuyer | theta_latency | 20ms | 远大于实测延迟，延迟维几乎恒为正 |
| QualityBuyer | theta_recall | 0.95 | 仅 nprobe=128 可达 |
| BudgetBuyer | alpha_price | 800 | 相对合理 |

### LatencyBuyer：θ 过大

nprobe=32，延迟 ≈ 3ms：

```
500 × (0.020 - 0.003) = +8.5   # 延迟维强烈正向
```

nprobe=8 与 nprobe=128 延迟项差别很小 → **不像延迟敏感买家**。

改用 `query.sla_t`（如 10ms）作锚点后，超 SLA 时该项可为负，才有区分度。

### QualityBuyer：θ_recall 过高

nprobe=32，recall ≈ 0.88：

```
30 × (0.88 - 0.95) = -2.1   # 长期偏不满意
```

策略易退化为「只有 nprobe=128 + 高价才易接受」。建议 `theta_recall` 调至 **0.88–0.90**。

### BudgetBuyer

价格维与 `reports/week1_notes.md` 记录一致，是三组中**最可用**的一维；配合问题 1 用 `budget_t` 作锚点后可更一致。

### 影响

- 效用上可能**只有价格在驱动** accept/reject
- 主实验 `reports/main_results.csv`：Fixed accept ~98%，LinUCB ~83%，revenue 略升 → 符合「 mainly 提价」

### 修复方向

1. 延迟维：用 `query.sla_t` 替代固定 `theta_latency`  
2. 召回维：`theta_recall` 降至 0.90 左右  
3. 重跑 `scripts/calibrate_buyer.py`、`scripts/diag_buyer_differentiation.py`  

---

## 三者的关系

```
问题 2：类型与 Query 不一致
    ↓
问题 1：sla/budget 不进买家
    ↓
问题 3：θ 与 FAISS 不对齐
    ↓
结果：名义三类买家，行为近似一类；策略 mainly 学提价
```

---

## 建议修复顺序

| 步骤 | 内容 | 文件 |
|------|------|------|
| 1 | 硬约束 + 效用用 query.sla_t / budget_t | `src/data/buyer_simulator.py` |
| 2 | build_query 与买家类型绑定 | `query_factory.py`、`run_experiment.py`、`compare_bandit.py` |
| 3 | 重标定 theta_recall 等 | `buyer_simulator.py` |
| 4 | 同步校准图 | `scripts/calibrate_buyer.py` |
